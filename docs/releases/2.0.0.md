# DataM8 Desktop 2.0.0

DataM8 2.0 replaces the previous Windows desktop application with a React/Electron
metadata editor and the DataM8 2.0 Python backend. This is the first regular v2
desktop release; the earlier v2 beta releases remain available separately.

## Highlights

- Edit solutions, zones, Base definitions, folders, model entities, attributes,
  relationships and transformation functions in the unified v2 workspace.
- Save through coordinated autosave, with dirty-state tracking, ordered saves,
  keyboard navigation and actionable errors.
- Browse connector sources, preview data, import metadata and compare/refresh
  existing entities. Connector-supplied descriptions and saved type mappings
  determine the import behavior.
- Use the builtin CSV, SQL Server, Azure Data Lake, ODCS and Databricks Unity
  Catalog connectors supported by the bundled backend. Live access requires
  the corresponding connection configuration and service permissions.
- Generate output through the solution's configured targets and templates.
- Check for updates manually from Help. Windows supports verified downloads and
  restart-to-install; macOS and Linux use verified manual replacement.

## Persistence and connector fixes

- Base renames and Property Value reassignment preserve the original JSON file,
  including custom filenames. Equal value names belonging to different
  Properties are handled separately.
- Folder rename moves the folder's own metadata and its descendants, retains
  IDs and assignments, and updates relative paths.
- Model entity rename preserves function filenames and supported legacy
  subfolder references. Deletion cleans up unshared referenced local function
  files while preserving shared, external and unrelated files.
- CSV navigation, metadata, preview and import accept the authentication field
  without passing it to the CSV reader, and repeated operations retain their
  connection configuration.

## Installation and compatibility

The release provides Windows x64 (NSIS EXE), macOS Intel and Apple Silicon
(DMG and ZIP for each), and Linux x64 (AppImage and DEB). Verify the downloads
using the supplied signatures and checksums before installation; see the bundled
`INSTALL-AND-VERIFY.md` and `BUILD-MANIFEST.json` for instructions and exact build
identities.

The application bundles Generator 2.0.0 at commit
`a9ad920ec505ee0b1153a6da0744c617017d01e5` and DataM8 Model 2.0.0 at commit
`591b796a962117ef2a1f9d807074bf3a4f5cc159`. Matching version labels alone do not
identify an earlier installation, because Generator 2.0.0 was reissued.

Back up solutions and application settings before replacing an earlier
installation. The new NSIS installer does not establish automatic migration
from the previous MSI application. Validate the documented replacement sequence
and older solutions on disposable copies before broad rollout.

V2 solutions, models, plugins and generator templates must follow the current
backend contract. Explicit plugin bindings and saved type mappings are required;
arbitrary v1 solutions or custom plugins are not automatically compatible. The
application does not repair previously damaged folder or function layouts.

Windows Authenticode and detached GPG signatures are verified by the release
process. Certificate trust depends on the configured signer and the target
machine. macOS uses ad-hoc application signing with detached GPG verification;
the packages are not Apple Developer ID signed or notarized. Do not interpret
successful CI installation as universal SmartScreen, Gatekeeper, or antivirus
approval.

## Verification

Publication requires successful quality checks, native builds and installed-app
verification on all four platform targets, plus signed Windows update tests,
negative signature tests and verification of the final signed distributions.
Only the resulting verified artifact is published. The exact release commit,
workflow and backend/schema pins are recorded in the build manifest and the
release provenance appended by the publishing workflow.

Tests use disposable fixtures. Live-cloud compatibility and the replacement of
an existing customer MSI installation require their own acceptance evidence.
